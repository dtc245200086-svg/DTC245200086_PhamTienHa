## 1. EXECUTIVE SUMMARY & FORENSIC EVENT LOG

During the execution of **Gate 4 (Customer Profile Status Mutation Hardening)**, an end-to-end test setup attempted to create a test user with the role `ROLE_BILLING_MANAGER`. PostgreSQL rejected the operation with:
```text
ERROR: value too long for type character varying(16)
```
To clear the blocking constraint and enable testing, a direct DDL command was executed against PostgreSQL:
```sql
ALTER TABLE public.users ALTER COLUMN role TYPE character varying(32);
```
Subsequently, this DDL command was incorporated into `db/migrations/08_p1_5_credit_risk_control.sql` at line 44.

This report documents the forensic history of this schema modification, demonstrates its alignment with the Frozen Specification, resolves the file-to-database synchronization state, and confirms 100% reproducibility on clean database deployments.

## 3. ROOT CAUSE ANALYSIS & FROZEN SPEC COMPLIANCE

### 3.1. Mathematical Root Cause
In PostgreSQL migrations 01 through 07, `public.users.role` was declared as:
$$\text{Type: } \text{VARCHAR}(16)$$
The maximum string length allowed was 16 characters.

In Milestone P1.5, the Master Specification introduced privileged roles for credit governance:
- `'admin'` $\to 5$ characters ($\le 16$)
- `'staff'` $\to 5$ characters ($\le 16$)
- `'ROLE_ACCOUNTANT'` $\to 15$ characters ($\le 16$)
- `'ROLE_AUDITOR'` $\to 12$ characters ($\le 16$)
- **`'ROLE_BILLING_MANAGER'` $\to 20$ characters ($> 16$)**

When Migration 08 was authored in Gate 1, Section 3 updated the check constraint:
```sql
ALTER TABLE public.users DROP CONSTRAINT IF EXISTS users_role_check;
ALTER TABLE public.users ADD CONSTRAINT users_role_check
    CHECK (role = ANY (ARRAY['admin', 'staff', 'ROLE_BILLING_MANAGER', 'ROLE_ACCOUNTANT', 'ROLE_AUDITOR']));
```
However, the underlying column declaration remained `VARCHAR(16)`. While the check constraint permitted `'ROLE_BILLING_MANAGER'`, any attempt to actually store `'ROLE_BILLING_MANAGER'` into `users.role` was halted by the column length limit of 16 characters.

### 3.2. Frozen Specification Compliance
In [`docs/BILLING_ONE_P1_5_OFFICIAL_SPEC.md`](file:///c:/Users/phamt/OneDrive/Desktop/Billing_One/docs/BILLING_ONE_P1_5_OFFICIAL_SPEC.md) (v1.0.0 Final Frozen):
- Section 2.1 & 3: Specifically mandates role `ROLE_BILLING_MANAGER` as the designated managerial authority alongside `admin` for `invoice.issue_override` and `customer.unlock`.
- Widening `users.role` from `VARCHAR(16)` to `VARCHAR(32)` is an absolute technical necessity to support the required string literal `'ROLE_BILLING_MANAGER'`.
- In PostgreSQL 16, widening a `VARCHAR` column length is an instant metadata-only operation requiring no table rewrite.

## 4. MIGRATION HISTORY & DRIFT RECONCILIATION

### 4.1. Chronological Event Sequence
1. **Gate 1 Execution:** Migration 08 script was drafted and executed in PostgreSQL. The check constraint was added, but the column remained `VARCHAR(16)`.
2. **Gate 2 & Gate 3 Execution:** Executed without issues because tests used existing users (`admin`, `staff`) or direct function calls.
3. **Gate 4 Execution:** Test suite T08/T07 required creating live test accounts with `ROLE_BILLING_MANAGER` and `ROLE_ACCOUNTANT`. PostgreSQL raised length error for `ROLE_BILLING_MANAGER`.
4. **Immediate Action:** DDL command `ALTER TABLE public.users ALTER COLUMN role TYPE character varying(32);` was executed directly in `billing-postgres-1`, and line 44 of `08_p1_5_credit_risk_control.sql` was amended to mirror the database.

### 4.2. Exact SQL in Migration 08 (`db/migrations/08_p1_5_credit_risk_control.sql`)
```sql

-- 3. EXPAND USERS ROLE CHECK CONSTRAINT (PRESERVING EXISTING DATA & ROLES)
-- ----------------------------------------------------------------------------

    CHECK (role = ANY (ARRAY['admin', 'staff', 'ROLE_BILLING_MANAGER', 'ROLE_ACCOUNTANT', 'ROLE_AUDITOR']));
```

### 4.3. Exact SQL in Rollback Migration (`db/migrations/08_p1_5_credit_risk_control_down.sql`)
```sql
-- 4. REVERT USERS ROLE CHECK CONSTRAINT & COLUMN TYPE (Warning: only if no users with new roles exist)
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM public.users
        WHERE role NOT IN ('admin', 'staff')
    ) THEN
        ALTER TABLE public.users DROP CONSTRAINT IF EXISTS users_role_check;
        ALTER TABLE public.users ADD CONSTRAINT users_role_check
            CHECK (role = ANY (ARRAY['admin', 'staff']));
        ALTER TABLE public.users ALTER COLUMN role TYPE character varying(16);
    END IF;
END $$;
```
