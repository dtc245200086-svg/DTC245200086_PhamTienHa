## 4. Kế hoạch Triển khai P1.2.1

1. **Migration `db/migrations/04_p1_2_1_payment_idempotency.sql`:**
   - Tạo bảng `public.payment_idempotency_keys`:
     - `id`: bigint generated by default as identity PRIMARY KEY
     - `idempotency_key`: varchar(255) NOT NULL UNIQUE
     - `request_hash`: varchar(64) NOT NULL (SHA-256 hex)
     - `payment_id`: bigint REFERENCES public.payments(id) ON DELETE SET NULL
     - `response_status`: integer NOT NULL DEFAULT 201
     - `response_body`: jsonb NOT NULL
     - `created_by`: bigint REFERENCES public.users(id)
     - `created_at`: timestamptz NOT NULL DEFAULT now()
   - Phân quyền: Cấp `SELECT, INSERT, UPDATE` cho `billing_app`, `SELECT` cho `billing_readonly`.
2. **Tích hợp Canonical Service ([paymentService.js](file:///c:/Users/phamt/OneDrive/Desktop/Billing_One/app/src/services/paymentService.js)):**
   - Bổ sung cơ chế quản lý Idempotency trong transaction:
     - Khóa 64-bit advisory lock: `SELECT pg_advisory_xact_lock(hashtext('idemp_payment'), hashtext($1))` trên idempotency key.
     - Kiểm tra sự tồn tại của `idempotency_key`.
     - Nếu đã tồn tại:
       - So khớp `request_hash`. Nếu khác $\rightarrow$ Reject 409 Conflict (`IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`).
       - Nếu khớp $\rightarrow$ Trả về `response_body` ban đầu, không tạo Payment hay Allocation mới.
     - Nếu chưa tồn tại:
       - Tạo Payment và Allocation bình thường.
       - Lưu bản ghi vào `payment_idempotency_keys` trước khi commit transaction.
3. **Tương thích ngược (Backward Compatibility):**
   - Nếu client không truyền `Idempotency-Key`: Luồng xử lý diễn ra bình thường như P1.2.
   - Áp dụng thống nhất cho cả `POST /api/payments` và `POST /api/invoices/:id/payments`.
4. **Kiểm thử Retry Matrix (10 test cases):**
   - Xây dựng [scripts/p1_2_1-idempotency-test.mjs](file:///c:/Users/phamt/OneDrive/Desktop/Billing_One/scripts/p1_2_1-idempotency-test.mjs) bao phủ toàn bộ 10 kịch bản retry, concurrency, payload conflict, unapplied cash conservation.
